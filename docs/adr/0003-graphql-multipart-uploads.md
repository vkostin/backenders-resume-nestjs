# ADR 0003: Загрузка файлов через GraphQL multipart, а не presigned URL

## Статус

Принято.

## Контекст

Собственная документация Apollo направляет загрузку файлов в сторону
presigned URL (S3 POST-политики), а не проксирования байтов через
GraphQL-сервер. 
Почему Presigned URL: не грузить большие файлы через API, позволяют 
передавать файлы напрямую из браузера в S3 и не требуют 
буферизации файлов в памяти.

В то же время загрузки в этом проекте - редкие административные действия, 
выполняемые из Apollo Sandbox.

## Решение

Загрузка идёт через спецификацию GraphQL multipart request с помощью
`graphql-upload-ts`:

- один файл на мутацию (`addProjectIllustration`, `setProfilePhoto`);
- весь поток — валидация, запись в S3, запись в БД — является одной
  GraphQL-операцией и проверяется end-to-end из Sandbox через элемент
  «Add files»;
- защита Apollo от CSRF остаётся включённой; multipart-запросы должны
  содержать заголовок `Apollo-Require-Preflight: true` (задокументировано
  в README).

## Последствия

- Путь загрузки виден и тестируем как обычная GraphQL-мутация — в том
  числе в наборе Jest/Testcontainers.
- Байты файла проходят через процесс API; допустимо при лимите 5 МБ и
  единичном пользователе.
- Если API когда-нибудь понадобится массовая или крупная загрузка,
  presigned URL станут правильным развитием — порт `MediaStorage` уже
  изолирует детали S3, поэтому изменение будет локализованным.

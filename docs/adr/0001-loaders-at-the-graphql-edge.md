# ADR 0001: DataLoader'ы на границе GraphQL

## Статус

Принято.

## Контекст

`Query.profile` возвращает один Profile, но полная выборка проходит по
ссылкам, категориям навыков, навыкам, опыту, проектам, достижениям и
иллюстрациям. Наивная реализация выдавала бы один SQL-запрос на каждую
родительскую строку — паттерн N+1, растущий вместе с каталогом.

## Решение

- Корневое поле `profile` разрешается один раз через `PortfolioService`,
  который возвращает единственную запись `ProfileRecord`.
- Каждое вложенное поле (`profile.links`, `experience.skills`,
  `project.illustrations`, …) разрешается per-request DataLoader'ом.
- DataLoader'ы находятся в `src/portfolio/loaders.ts`, создаются фабрикой
  `GRAPHQL_CONTEXT_FACTORY` один раз на GraphQL-запрос и вызывают
  read-порт `PortfolioQueries` пакетно (`findXByIds`).
- Резолверы не содержат вызовов Prisma и SQL; они только отображают
  записи в GraphQL-типы и обращаются к DataLoader'ам.

## Последствия

- Выборка только скаляров (`profile { name }`) стоит ровно один SQL-запрос.
- Полный граф стоит ограниченное число запросов независимо от размера
  каталога (16 выражений для текущего сида, проверяется в
  `test/api.spec.ts`).
- Добавление новой связи означает: batch-метод на `PortfolioQueries`,
  DataLoader и field resolver — три маленьких локальных изменения.
- DataLoader'ы per-request, поэтому состояние не утекает между запросами
  и кэширование не может устареть.

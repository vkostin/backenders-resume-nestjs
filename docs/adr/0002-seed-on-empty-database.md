# ADR 0002: Seed запускается только на пустой базе данных

## Статус

Принято.

## Контекст

API предоставляет мутации, позволяющие владельцу редактировать каждую
сохранённую сущность. Две возможные политики сидирования конфликтуют с
этим:

- **Сидирование при каждом запуске** (поведение v1): база данных
  приводится к каталогу при каждом перезапуске контейнера, молча
  уничтожая все правки, сделанные через мутации.
- **Никогда не сидировать автоматически**: чистый `docker compose up`
  даёт пустой портфолио, что нарушает требование задачи — приложение
  должно работать с чистого запуска.

## Решение

Entrypoint (`docker/entrypoint.sh`) выполняет по порядку:

1. `prisma migrate deploy`
2. `seed` — который заполняет базу данных **только когда в ней нет
   строки Profile**
3. запуск сервера

Явный `SEED_RESET=1` принудительно записывает каталог заново, заменяя всё
сохранённое. `SEED_MEDIA=full|none` определяет, будет ли сид
обращаться к Silo и записывать строки медиа.

## Последствия

- Первый запуск на чистой базе данных создаёт полный каталог,
  сразу видны данные в Apollo Sandbox.
- Перезапуски сохраняют результаты мутаций; ничего не откатывается
  молча.
- `SEED_RESET=1` — задокументированный способ вернуть каталог.
- Сид остаётся единственным писателем, обходящим правила мутаций; он
  записывает каталог в одной транзакции и идемпотентен по построению.
